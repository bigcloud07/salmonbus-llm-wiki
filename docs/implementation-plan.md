# 구현 계획

파일 기반 분석 첫 버전을 구현했습니다. 합성 자료로 실행과 연결을 검증했으며 실제 평가 자료와 운영 상태는 미확인입니다. 2026-10-28에 1단계의 문서·코드 조사를 수행했으며, 운영 데이터와 배포 상태의 검증은 남아 있습니다. 공개 가능한 결과는 [데이터 요구사항](data-readiness.md)에 기록했습니다. Wiki 작성과 자동화는 아직 실행하지 않았습니다.

## 1. 자료와 정의 조사

- 예측 모델 관련 Confluence 원본과 코드 위치를 확인합니다.
- 실제 모델 이름, 최신 설계, 제안과 확정 사항을 대조합니다.
- Amplitude의 이벤트, 속성, 내보내기 또는 API 접근 방법을 확인합니다.
- DB 예보 평가 집계의 컬럼과 생성 환경을 확인합니다.
- 두 자료의 연결 기준, 시간대, 누락과 중복 가능성을 확인합니다.
- Day 7 리텐션과 예보 평가 지표의 정의를 팀과 확정합니다.

완료 기준: 실제로 답할 수 있는 첫 질문과 필요한 자료 목록, 연결의 한계를 설명할 수 있습니다.

## 2. 한 주제의 Wiki 만들기

예측 모델 설명, 핵심 용어, 관련 DB 사전, 결정과 미정 사항을 작성합니다. 출처와 버전을 붙이고 주제를 아는 팀원이 확인합니다.

완료 기준: 팀원이 모델의 목적과 흐름을 이해하고, 중요한 설명의 원본을 찾을 수 있습니다. 제안이 확정 사항으로 잘못 기록되지 않습니다.

## 3. 파일로 분석 하나 완성하기

같은 기간의 Amplitude 자료와 내부망에서 만든 예보 평가 집계 파일을 사용합니다. 연결과 계산은 코드로 수행하고, LLM이 Wiki의 정의와 변경 이력을 참고해 결과를 설명합니다.

완료 기준: 기준 집계와 계산을 대조할 수 있고, 관찰 기간 부족·연결 실패·누락 자료를 드러냅니다. 결과에서 사실과 가설을 구분하며 계산을 재현할 수 있습니다.

## 4. 필요한 부분 자동화하기

파일 기반 흐름의 유용성을 확인한 뒤 자료 수집, 변경 감지, Wiki 변경안 생성, 검토 후 반영을 자동화합니다. 권한 변경, 원본 삭제, 동시 편집, 실행 실패와 재시도를 다룹니다.

완료 기준: 원본 변경이 관련 Wiki의 변경안으로 이어지고, 사람의 수정과 권한을 보존합니다.

## 구현 구성요소

| 구성요소 | 최소 책임 |
| --- | --- |
| 자료 수집 | 출처, 버전, 시각, 권한과 함께 자료 읽기 |
| Wiki 갱신 작업 | 영향 문서 탐색, 근거가 있는 변경안 생성 |
| 질문 에이전트 | Wiki 탐색, 데이터 로드, 분석 실행, 답변 생성 |
| 분석 코드 | 지표 계산, 집단 비교, 데이터 연결과 검증 |
| 관리 저장소 | 원본 처리 버전, 원본-Wiki 관계, 검토 상태, 실행 결과 |

도구 이름의 예시는 `search_wiki`, `read_source`, `load_retention_data`, `load_forecast_evaluation`, `run_analysis`, `propose_wiki_update`입니다. API 계약이나 구현이 확정된 것은 아닙니다.

## 미정 사항

- 실제 자료의 접근 권한과 공개 가능 범위
- 리텐션과 예보 품질의 계산 정의
- 데이터 연결 키와 분석 가능한 단위
- 내부망 집계 파일의 생성 주기와 안전한 전달 위치
- Wiki 변경안 검토 담당자와 반영 절차
- 모델, 실행 환경, 관리 저장소, 비용 한도
- 데이터 보관 및 삭제 기간

## 첫 범위에서 제외

별도 채팅 UI, 실시간 DB 직접 조회, 전체 이벤트 복제, 대규모 검색 인프라, 정기 자동 원인 분석은 처음부터 만들지 않습니다. 현재 사용 중인 에이전트 환경에서 한 주제와 한 질문을 검증합니다.

## 공개 저장소 운영

설계, 일반화된 코드, 합성 테스트 데이터만 공개합니다. 내부 자료와 실제 사용자 데이터를 배치할 로컬 경로는 Git에서 제외합니다. `.gitignore`는 실수 방지 장치일 뿐이므로 commit 전 실제 파일 내용을 검토해야 합니다.
