# 첫 분석을 위한 데이터 요구사항

기록일: 2026-10-28. Confluence의 관련 문서와 로컬 코드에 대한 1차 정적 조사를 수행했다. 내부 자료의 세부 내용과 출처는 비공개 조사 메모로 보관한다. 이 문서는 공개 가능한 분석 계약 초안이다.

운영 Amplitude, DB, 배포 상태와 실제 데이터는 검증하지 않았다. 리텐션 하락이나 예보 품질 악화를 관찰했다는 뜻이 아니다.

## 첫 질문

“팀이 선택한 재방문 지표가 비교 기간 사이에 실제로 하락했는지 확인하고, 같은 이용 환경의 예보 품질 변화와 비교한다.”

정확히 Day 7, Day 7~13 구간, 주간 언바운디드 재방문은 서로 다른 지표다. 시작 이벤트와 재방문 이벤트도 동일하게 고정해야 한다. 정의가 확정되기 전에는 차트 이름만으로 계산 방식을 선택하지 않는다.

## 조사 결과가 설계에 주는 영향

- 학습용 문서에는 개념, 모델 코드의 현재 동작, 실제 배포 상태를 구분해서 기록한다.
- 분석 이벤트와 DB의 내부 식별자가 같다고 가정하지 않고 매핑을 확인한다.
- 기존 평가 집계와 로그를 재사용할 수 있는지 먼저 검토한다. 신규 집계 코드부터 만들지 않는다.
- 상세 평가, 축약 저장, 보관 파일이 있다면 분석 기간의 전체 범위를 포함하는지 확인한다.
- 제안 문서의 이벤트를 실제 구현되거나 운영 수집 중인 이벤트로 간주하지 않는다.
- 현재 분석의 최대 해석 범위는 자료 확보 후 정한다. 개별 예보 노출 연결이 없으면 집단 수준의 관찰 분석으로 제한한다.

## 필요한 자료

아래 이름은 내보내기 계약의 논리적 항목이다. 실제 테이블이나 이벤트 필드명, 구현 완료 API가 아니다.

| 자료 | 최소 항목 | 검증할 조건 |
| --- | --- | --- |
| 분석 정의 | 시작·재방문 이벤트, 기간 방식, 시간대, 필터, 사용자 식별 기준 | 두 비교 기간에 동일한 정의 적용 |
| 리텐션 집계 | 시작 집단, 관찰 종료일, 분모, 재방문자 수 | 관찰 완료, 분자 ≤ 분모, 분모 0은 결측 |
| 사용 환경 | 기간, 노선, 방향, 모델 버전, 필요한 앱 버전 | 실제 수집 여부와 속성 누락률 |
| 예보 평가 | 기간, 대상 집단, 지표의 합계와 유효 표본 수 | 평가 상태와 제외 기준, 중복 제거 |
| 매핑 | 외부·내부 노선 ID, 노선 판본, 정류장, 모델 배포와 버전 | 유효기간, 일대다 관계, 연결 누락률 |
| 변경 기록 | 배포, 모델 변경, 장애, 유입 변화의 시각과 근거 | 관찰 사실과 추정 구분 |

사용자별 노출 분석이 필요하면 가명 사용자 식별자와 실제 예보 식별자의 연결이 추가로 필요하다. 단순 리텐션 집계표와 전체 예보 평균만으로 사용자별 경험을 복원하지 않는다.

## 평가 지표의 후보

이 항목은 첫 추출 계약의 제안이다. 최종 분석 지표와 자격 조건은 담당자와 확정한다.

- 좌석 MAE: 유효 평가의 절대 오차 합계 / 해당 유효 평가 수.
- 만석 Brier score: 유효 평가에서 (예측 만석 확률 − 실제 만석 여부)의 제곱 합계 / 해당 유효 평가 수.
- 제공 실패와 평가 결측·제외 상태의 건수 및 비율: 성공적으로 평가된 사례만 보는 편향을 확인한다. 제공 실패와 평가 실패는 다른 지표다.

구간 평균을 단순 평균하지 않고 합계와 분모를 합쳐 계산한다. 분모가 다르면 지표마다 따로 보존한다. 표본 수와 집단 구성이 바뀌었는지도 함께 보고한다.

## 시간과 연결 규칙

- 사용자 이벤트 발생, 예보 생성, 입력 관측, 실제 도착, 평가 확정, 로그 출력 시각을 구분한다.
- 집계 주기의 출력 시각을 개별 예보 발생 시각으로 대체하지 않는다.
- 누락, 중복, 재처리, 보관 파일 이동, 배포 변경을 점검한다.
- 사용자 집단은 시작 시점 기준으로 분류한다. 미래 행동으로 집단을 나누면 해석이 왜곡될 수 있다.
- 서로 다른 노선·모델·예보 거리의 구성 비중이 달라지면 전체 평균만으로 품질 악화를 판단하지 않는다.
- 원인을 단정하지 않는다. 노선·시간대 수준의 연관성은 특정 사용자의 실제 예보 노출에 대한 증거가 아니다.

## 다음 작업

1. 분석할 재방문 지표의 정확한 정의를 선택한다.
2. Amplitude의 읽기 전용 접근 또는 내보내기 파일을 확보한다.
3. 내부 환경 담당자가 동일 기간의 평가 집계 및 식별자 매핑을 제공한다.
4. 작은 자료로 연결률, 누락률, 기준 집계와의 일치를 확인한다.
5. 연결 가능한 범위에서 계산 코드를 작성하고 검토한 분석 보고서를 남긴다.

현재 완료: 문서·코드의 1차 조사와 요구사항 초안. 미완료: 실제 데이터 확보, 운영 배포 대조, 연결 검증, 수치 계산.
